Zero-Drift Idempotency, Retry Resilience & Double-Debit Prevention

When transacting real money across third-party banking APIs, transport timeouts are inevitable. The challenge is ensuring that network retries never produce duplicate charges, double holds, or lost-update race conditions.

cd0df30a Reliability Architecture

RBL Idempotent Redemption Tracking & Retry Resilience

The Problem

RBL redemption followed a two-step Block → Redeem flow. A network timeout mid-flow left points locked in hold with no safe way to retry. Upstream retries generated fresh timestamped client transaction IDs, causing RBL to treat them as brand-new redemptions (duplicate holds and customer double-charge risk).

Engineered Solution
  • Engineered stableRBLClientTxnID() derived deterministically from billTxnID_precheckoutID, allowing RBL's native deduplication on (clientTransactionId + Idempotency-Key) to engage across network retries.
  • Built isUnknownRBLRedeemOutcome() to decouple transport ambiguity (context.DeadlineExceeded, HYSTRIX: TIMEOUT, 504 Gateway Timeout) from definite rejections. Ambiguous calls stay IN_PROGRESS (hold maintained); definite failures record FAILED and trigger best-effort release.
  • Implemented resume logic: prior SUCCESSFUL state short-circuits without outbound calls; IN_PROGRESS skips the Block step and directly re-redeems the stored blockResponseId.
  • Routed transient errors to RetriableIssuerApiError(canRetry=true) for automated asynchronous background retry instead of hard user-facing failures.

fd9dec15 Concurrency & Double-Debit Fix

RBL Idempotent Refund & Atomic Counter Update

The Problem

Cron-driven refund re-drives transmitted timestamped refund request IDs, causing RBL to execute duplicate refunds. Concurrently on our side, each redrive inserted an additional reversal row and re-incremented total_refund_points via unsafe read-modify-write struct cycles.

Engineered Solution
  • Stabilized refundRequestID to the canonical Twid refund ID, triggering RBL's native code 2012 (already processed) instead of debiting again.
  • Engineered ErrRefundAlreadyProcessed sentinel and defensive parsing across raw response payloads (handling untyped error arrays) to treat 2012 as verified success.
  • Rewrote SaveExternalBrandPointsRefundDetails into a single atomic GORM transaction with check-then-insert deduplication on (bill_transaction_id, refund_request_id).
  • Replaced read-modify-write counters with database-level atomic expression gorm.Expr("total_refund_points + ?"), completely eliminating lost-update race conditions.

Architectural Principles

Structural, not instructional, safety at the AI boundary.

An LLM handed a job description and a master resume will hallucinate toward the job description — inventing skills or inflating metrics. A prompt saying "don't invent things" is not a reliable control. JobClaw enforces safety structurally:

1
Two Distinct State Machines: Jobs (DISCOVERED → SCORING → SHORTLISTED → APPROVED) are strictly separated from Applications (DRAFT → READY_TO_APPLY → SUBMISSION_IN_PROGRESS). An application cannot physically exist for an unapproved job.
2
Deterministic Fact-Guard: resume_fact_guard.go verifies every metric, company, date, and technology traces back to the master resume before compiling to LaTeX/PDF. Failing checks reject and regenerate.
3
PII Structural Isolation: Candidate contact and education data are injected from candidate.yaml and never pass through the LLM prompt, placing high-stakes data outside model reach.
4
Ambiguity as a First-Class State: An unknown submission outcome locks the row in SUBMISSION_IN_PROGRESS for manual reconciliation, exits with code 2, and is never auto-retried.

func (fg *FactGuard) VerifyAndRender(ctx context.Context, gen *LLMOutput) (*ResumePDF, error) {
  // 1. Deterministic validation against master resume
  if err := fg.Validator.AssertBounds(fg.Master, gen); err != nil {
    return nil, fmt.Errorf("fact-guard failure: %w", err)
  }

  // 2. Keep contact & education structurally isolated
  gen.Contact = fg.Master.DeterministicContact
  gen.Education = fg.Master.DeterministicEducation

  // 3. Cost-optimized LaTeX PDF rendering ($0.0049/resume)
  return fg.CompileLaTeX(ctx, gen)
}
